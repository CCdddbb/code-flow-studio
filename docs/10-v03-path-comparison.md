# v0.3 第二阶段：参考路径终点对比

版本：`0.3.0-alpha.2`。本轮只迭代 Code Flow Studio，没有改动原业务仓库、独立 Demo 或 A 股项目。

## 用户任务

从“逐步看一条路径”补到“核对两条路径的结果有什么不同”。尤其不能因为成功与恢复都到达相同终态，就声称恢复正确、结果一致或没有重复写入。

在「参考场景」展开「路径对比」：左侧使用当前场景路径，右侧任选另一条，也允许自比较。支持交换左右、只看差异/全部叶字段及展开每个逻辑存储的操作轨迹。对比始终使用整条路径的终点，不随播放器当前步骤改变。默认折叠，避免把主步骤视图挤满。

## 纯比较模型

`public/scenarios.js` 增加 `compareScenarioPaths(model, leftId, rightId)`，复用现有校验与确定性运行器：

- 每侧记录路径 ID/名称/类型、终态、步骤数量与显式操作数量。
- 每个逻辑存储保留两侧最终记录、按步骤排列的显式操作及字段差异。
- 字段变化为 `same`、`different`、`left-only`、`right-only`。
- 嵌套对象递归比较，键顺序不影响判断；字段路径为键数组，避免将 `a.b` 键名误解成两层路径。
- 字段存在性独立记录，不把不存在当成 null；相同空对象在全部字段模式中保留。
- 返回数据深拷贝，不修改目录、模型、先前模拟帧或另一侧结果。相同输入确定。

不新增分析模型字段、Schema 版本、服务端比较 API 或用户数据入口。UI 只消费内置公开参考模型，DOM 通过 `textContent` 创建，不将字段/值当 HTML 或脚本。

## 两个案例的实际对照

### 草稿成功 / 超时后恢复

两个作者指定路径都到达 `submitted`，但最终快照不同：

- `draft-store.revision`：成功为 4，恢复为 3。
- `submission-store.outbox`：成功为 `PENDING`，恢复为 null。

这揭示参考模型的两条路径尚未表达相同的版本/Outbox 行为。没有为制造漂亮演示而悄悄修改参考模型，也没有将这一差异外推为用户真实业务的问题。

### 订单成功 / 重试交付

最终状态和记录一致，但成功为 2 步、恢复为 3 步。页面保留显式操作轨迹，仍然不声称运行等价、去重有效或真实消息系统不存在重复交付。

## 必须保留的边界

- 所有结果仍是 `authored-assumption`，不变成 `source`、`user-confirmed` 或真实数据库记录。
- set/unset/increment 的数量不是数据库写入次数；同值 set、未存在字段的 unset、存储批处理等均可能具有不同运行语义。
- 终态相同、快照相同、步骤相同是不同维度，任何一项都不能证明事务、幂等性或恢复正确。
- 不评估文本条件，不对齐“第 N 步”的运行时间，不模拟性能、事务回滚或外部副作用。
- 不引入自定义场景导入/编辑、源码关联、确认记录或规则断言。这些仍需独立来源/安全设计。

## 分享与兼容性

内分析 `1.0.0`、分享 `share-1.0.0`、参考模型 `scenario-1.0.0` 均不变。原白名单重建、风险确认和披露级别限制不变。

三种 HTML 的公开应用资源中均内置比较函数和 UI；分析 JSON 不包含比较选择、对照结果或临时模拟帧。离线再导出固定最初页面，不序列化被修改的 DOM。旧 HTML 是冻结快照，需要重新导出才能获得新功能。

没有新增依赖、AI、外部请求或业务数据库连接；没有读取私有实现。界面仍为原生 HTML/CSS/ES Modules，与原工作区样式保持一致。
