# 分析与可视化契约 v0.1（设计草案）

本文件保留最初的目标契约草案，其中场景、事务与数据库快照等字段尚未实现。当前实际契约是 `schema/analysis.schema.json` v1，见 [实现说明](05-implementation.md)。不要将本草案当作现行 API。

## 1. 顶层结构

| 字段 | 用途 |
| --- | --- |
| `schemaVersion` | 契约版本；不兼容版本必须显式迁移或拒绝 |
| `project` | 展示名、语言、分析范围、选定入口 |
| `sourceSnapshot` | 文件相对路径、文件内容摘要、分析时间、解析器版本 |
| `entities` | 通用节点：actor、service、adapter、store、queue、external |
| `contracts` | DTO、请求/响应、字段类型与已识别约束 |
| `steps` | 通用步骤、条件、操作、数据输入输出、证据 |
| `flows` | 节点间的调用、数据、事件、返回、未解析连接 |
| `transactions` | 候选/确认的事务边界、传播方式、归属步骤及依据 |
| `fieldMappings` | 字段来源、目标、变换、证据、解析状态 |
| `scenarios` | 演示输入、分支路径、状态与存储变化 |
| `evidence` | 证据索引；步骤引用 ID，不重复塞入源码 |
| `assumptions` | 演示假设、人工确认及修订记录 |
| `diagnostics` | 错误、警告、未知依赖及支持覆盖报告 |
| `presentation` | 布局类型、主题、标题与初始视图，不承载业务逻辑 |

运行文件应使用项目内相对路径；本地绝对 sourceRoot 放在不导出的配置中。

## 2. 可信度必须分维度

不要用一个“可信度 90%”掩盖不同含义。

- **结论来源 `basis`**：`source` / `inferred` / `user-confirmed` / `unknown`。
- **数据模式 `dataMode`**：`mock` / `observed` / `unknown`。
- **证据有效性 `evidenceStatus`**：`valid` / `stale` / `missing`。

`observed` 预留给未来受控执行采集；首期不生成此类数据。人工确认不会自动升级为源码事实。源码里存在某方法，也不能单独证明调用发生或部署生效。

## 3. 证据契约

证据至少包括：

- `id`、项目内相对文件路径、符号名、原始起止行。
- `fileHash`：原文件完整内容的 SHA-256。
- `excerptHash`：未经脱敏的原始片段摘要，供本地核验。
- `claim`：该片段具体支持什么结论，避免“有引用即有证明”。
- `excerpt`：可选的脱敏展示片段，标记 `redacted`；不对脱敏片段冒充原始摘要校验。

证据刷新需重新提取和重新评估受影响结论。文件变化时先标记陈旧，不能静默移动行号后继续声称已验证。浏览器读取的是导出快照，不是实时文件系统。

## 4. 步骤与分支

步骤至少包括 `id`、`label`、`kind`、`entityId`、`basis`、`evidenceIds`、`inputRefs`、`outputRefs`。无法解析行为时允许输出未知，不强制模拟。

分支至少包括 `id`、进入条件、条件来源、`stepIds`、终止结果。拒绝、失败和恢复是不同概念；失败不能自动接上成功路径。

- 循环/重试在图里表示为边；播放场景是有长度上限的展开路径。
- `UNKNOWN` 是结果状态，不是“空表”或“失败”。
- 没有适配器实现时展示连接缺口，不能生成成功写入。
- 事务确认丢失需要核查依据，不能直接画成回滚。

## 5. 快照、操作与字段差异

业务对象、数据库记录、未知观察必须分开建模。数据库记录使用 `storeId + collection/table + key` 标识，主键字段由模型声明；不能固定 `_id/id/ID_` 猜测。

场景操作类型：

| 操作 | 意义 |
| --- | --- |
| `insertRecord` | 显式新增记录 |
| `patchRecord` | 修改给定字段，未提到的字段保留 |
| `unsetFields` | 显式删除字段 |
| `deleteRecord` | 显式删除记录 |
| `observeProjection` | 新获得选定字段快照，不推导其刚被插入 |
| `setObservationUnknown` | 当前观察不可知，不改写持久状态 |

每次投影都标记 `completeness: selected-fields | complete`。不完整投影中遗漏记录不能推导删除。嵌套字段用 JSON Pointer 表达，数组首期按整体比较，避免误用索引当作稳定身份。

展示差异分为 added、changed、removed、same、newly-observed、unknown。真正写入变化与新获得观察分别展示。

## 6. 演示转换的安全边界

首期提供有限声明式规则：copy、rename、常量、字段选取、对象封装、受支持类型转换、受约束状态更新。规则既要通过 Schema，也要在允许操作注册表中存在。

禁止把模型输出当作可执行代码，禁止 eval 或动态 SQL。不能解析的计算输出 unknown；用户确认的示例值带 assumptionId，不伪装为代码计算结果。

## 7. 必须执行的校验

1. Schema：类型、必填项、枚举、版本合法。
2. 引用：节点、证据、步骤、字段、场景路径 ID 均有效。
3. 证据：源码事实需有效证据；摘要/行范围和文件一致。
4. 语义：分支终止、记录身份、状态合法性、幂等与事务规则（仅对已声明且有依据的规则检查）。
5. 模式：MVP 禁止 observed；推断和 mock 标签不能被展示层隐藏。
6. 安全：导出无密钥/连接串/越界路径；文本和代码片段必须转义，不以 HTML 执行。
7. 输出：断裂图、空场景、未支持转换与未知结果需要明确降级说明。

硬错误阻止生成正式输出；软警告允许输出带提示的局部分析。校验失败时不回退到编造的“成功示例”。

## 8. 通用性约束

渲染器不得包含 `draft_records`、`flow_baoxiao`、`DraftSubmissionCoordinator` 等业务名称判断；业务名称只允许出现在模型和测试夹具中。流程类型决定布局，不决定业务结果。
