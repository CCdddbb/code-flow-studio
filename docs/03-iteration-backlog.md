# 迭代路线与自我迭代机制

> 历史路线和目标门禁。本文件的任务清单是最初规划，不是当前完成报告；当前交付状态见 [交付报告](04-delivery-report.md)。

## 1. 阶段交付

| 阶段 | 交付物 | 完成门槛 |
| --- | --- | --- |
| S0 方案沉淀（本次） | 定位、方案、契约草案、任务与评估机制 | 明确旧 Demo 与新项目边界，不把规划称为实现 |
| S1 参考基线 + 通用播放器 | 脱敏夹具、Schema、校验器、通用页面 | 用模型重放草稿案例，不使用业务硬编码 |
| S2 代码事实提取 | 文件索引、Java 解析、入口/调用/字段/证据 | 输入选定模块与入口，输出事实与未解析依赖 |
| S3 自动场景生成 | 规则提取、确定性样例、数据流程、分支 | 支持范围内生成场景；不能推导时可解释地阻断 |
| S4 泛化验证 | 第二个独立业务样例、CLI、静态站点导出 | 换输入不换渲染器；重复生成结果稳定 |
| S5 增强 | 更多框架/语言、模型归纳、可视化编辑 | 每种新能力配独立测试和覆盖说明 |

MVP = S1–S4，不仅是第一张可视化页面。

## 2. 接下来优先做的任务

### P0：参考答案和契约

- [ ] 将旧 Demo 的规则、场景、证据整理为独立基线，区分源码依据与人为演示数据。
- [ ] 不复制整个业务仓库；建立授权、脱敏与夹具更新流程。
- [ ] 将契约草案落实为 JSON Schema 和类型定义。
- [ ] 实现结构、引用、证据、模式与安全校验。
- [ ] 测试未知结果、显式删除、部分投影、失败独立终止等边界。

### P0：通用页面

- [ ] 通用实体/边布局，步骤播放器与分支切换。
- [ ] 字段 diff、数据库投影、事务区块、源码抽屉。
- [ ] 所有来源与 mock 标签可见，键盘导航与窄屏无阻断。
- [ ] 无外部资源依赖的静态导出；源码摘录默认不包含在公开分享包。
- [ ] 搜索并测试禁止草稿业务名称出现在渲染逻辑中。

### P1：真正从代码生成

- [ ] 解析器选型实验：DTO、普通调用、接口多实现、注解、跨文件引用。
- [ ] 只读扫描器：允许路径、文件类型、数量/大小上限、符号链接越界防护。
- [ ] 显式入口选择、事实模型与有效证据导出。
- [ ] 已支持 Spring/持久化模式适配；未支持模式进入诊断报告。
- [ ] 受限模拟转换与可重复演示数据，不执行生成代码。
- [ ] 源码变化后证据失效及受影响场景提示。

### P1：第二案例与打包

- [ ] 选择非草稿、规模较小的 CRUD 或状态流转模块；需要用户确认代码范围。
- [ ] 同一生成流水线和渲染器通过两个案例。
- [ ] 固定源码与种子时，规范化结果相同（排除分析时间等元数据）。
- [ ] 导出机器可读质量报告、模型 JSON 与站点。

## 3. 自我迭代不是“无限重写页面”

每个开发周期执行以下闭环：

```text
提出目标 → 生成/修改 → 结构校验 → 语义检查
        → 浏览器回归 → 质量报告 → 定位失败 → 有针对性修正
```

每轮默认最多 3 次自动修正；仍失败则保留诊断并进入人工确认，不能绕开校验或无限循环。只在当前工作区或临时目录修正，不能修改被分析仓库。外部模型调用设置单轮成本/次数上限。

### 质量门禁

| 维度 | 如何测量 | MVP 门槛 |
| --- | --- | --- |
| 结构正确 | Schema 与引用校验 | 硬错误 0 |
| 证据完整 | 源码事实步骤有有效证据 / 源码事实步骤总数 | 100%；不等于分析覆盖了全部代码 |
| 关键事实召回 | 人工基线关键事实被正确表达的比例 | 各案例关键事实全部覆盖或明确未知；关键错误 0 |
| 支持范围覆盖 | 已解析、部分解析、未解析节点数量 | 全部披露，不能通过删节点伪造覆盖率 |
| 真实性 | 假实现、mock 冒充 observed、推断冒充源码 | 0 项 |
| 数据语义 | 快照、diff、版本、幂等、失败边界测试 | 必测用例全部通过 |
| 通用性 | 第二个独立业务无需业务渲染分支 | 必须通过 |
| 安全 | 输入不执行、路径检查、敏感输出、HTML 转义 | 必测用例全部通过 |
| 交互 | 回放、切换、重置、键盘、窄屏 | 浏览器测试通过 |

### 每轮报告

记录输入快照、解析器/模型/规则版本、目标、变更、测试命令与结果、未解析项、人工修订次数、剩余风险和下一步。没执行的测试写“未执行”，不写“通过”。

优先级：**安全与事实正确 > 数据语义 > 泛化能力 > 交互 > 视觉装饰**。

## 4. 方案自身的三轮审视（设计层面，非运行验收）

### v0：复制旧页面，替换标题与 JSON

问题：能快速展示，但不能分析新代码；数据库、表单与播放器绑定草稿案例。

改进：将页面和业务解耦，用统一中间模型驱动展示。

### v0.1：让模型直接读仓库并生成 HTML

问题：容易编造业务语义、泄露源码、生成不可复核转换；重复生成不稳定。

改进：静态事实与模型归纳分离，证据先行；使用受限转换与模板渲染。

### v0.2：追求全语言、全仓库、全分支

问题：范围失控，入口歧义与动态行为难以证明，第一闭环迟迟无法验收。

改进：Java/Spring 单入口起步，明确未知；以草稿案例回归和第二案例泛化作为阶段门禁。
